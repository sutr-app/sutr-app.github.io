rustメモリキャッシュcrateメモ

2022-03-03·1 分
目次
要件: #
  • ttl設定可
  • アトリビュート設定だけではなく任意に設定、取得可
  • スレッドセーフ、非同期対応
  • LRU, LFU, アダプティブあたりのキャッシュができるとよい
  • 暗号化は特に必要ない
候補: (要件外のものも含めて検索したもの) #

moka-rs/moka: A high performance concurrent caching library for Rust (github.com)

  • LRU, LFUベースの色々なアルゴリズムがありそう
  • 採用実績がありそう

al8n/stretto: Stretto is a Rust implementation for https://github.com/dgraph-io/ristretto. A high performance memory-bound Rust cache.

  • LRU, LFUベースの色々なアルゴリズムがありそう
  • メトリクス取得に対応 (他のも取りようはあるはず？)
  • go のristretto のrust実装 (ristrettoのベンチマーク: Start.io | Why We Chose Ristretto Cache for Golang?

al8n/caches-rs: This is a Rust implementation for popular caches (support no_std). (github.com)

  • LRU, LFUはあるがttlサポートが将来の実装予定でまだない (発展途上)

ArtBlnd/endorphin: Key-Value based in-memory cache library which supports Custom Expiration Policies (github.com)

  • HashMapにTTL設定を追加したシンプルなメモリキャッシュ
  • 追い出しポリシー的なものはないかも？

ZeroTwo-Bot/cache-loader-async-rs: Thread Safe Cache with async loader functions based on tokio-rs (github.com)

  • LRU実装、TTLありで非同期対応のシンプルそうなcrate

jaemk/cached: Rust cache structures and easy function memoization (github.com)

  • アトリビュート設定だけだった

とりあえず現時点で一番高機能そうなstrettoをつかってみる

あとで余裕ができたらベンチマーク取ったりするかもしれない

追記: #

tonic でgrpcサーバに持たせようとするとDebugの実装を要求されて無理だった。これどうするかな。。。(自動生成のServerがDebug要求しないでほしいというのはある)

追記2: #

debug_stub_derive - Rust を使うと外部crateのtraitに対してもDebugをでっちあげられるということがわかった。

更に追記 #

strettoは内部のtracingログのレベルが微妙なのと開発状況としてmokaの方がよさそうなのでmokaに移りかけている。
